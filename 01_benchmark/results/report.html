5Pass 2 — result and key finding

ModelBest parameters foundbase PR-AUCtuned PR-AUCΔ
LightGBMnum_leaves=63, n_estimators=500, min_child_samples=20, lr=0.10.07930.0612▼ −0.018
CatBoostdepth=8, iterations=500, lr=0.10.07950.0697▼ −0.010

Grid tuning made both models worse on the test set. The mandated StratifiedKFold(shuffle) splits windows at random, but consecutive windows overlap 39/40 snapshots and share a job — so near-duplicate rows land in both the train and validation folds. That leak inflated cross-validation to AP ≈ 0.62–0.71 while true test PR-AUC ≈ 0.06 (a 10× gap).

Optimizing that leaky score, the search picked the most complex setting in every dimension (LightGBM num_leaves=63/500 trees; CatBoost depth=8/500 iters) — models that memorize the duplicated windows and then overfit the genuinely-held-out temporal test set.

Recommendation: report the base CatBoost (or LightGBM — tied at ≈ 0.079) as the selected model. A GroupKFold(groups=slurm_id) CV — no job spanning folds — is the correct fix and would let tuning actually help.

6Which failure types are predictable

Per-state recall@0.5 (share of pre-failure windows caught), base leading models.

Failure staterecall@0.5Interpretation
OUT_OF_MEMORY~0.66most predictable — gradual memory pressure has a clear pre-failure signature
TIMEOUT~0.52long-running degradation, detectable
FAILED~0.42heterogeneous causes
NODE_FAIL~0.40hardest — often an instantaneous hardware fault with little warning

The model catches the gradual failure modes and struggles with the instantaneous ones — the expected physical behavior, and the core challenge stated for the task.
